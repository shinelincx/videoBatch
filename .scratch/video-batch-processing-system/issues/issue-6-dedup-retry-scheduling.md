# Issue #6: 重复检测 + 重试机制 + 任务调度与状态同步

**标签**: `ready-for-agent`

**类型**: AFK

**被阻塞于**: #4, #5

---

## 构建什么

实现 pHash 重复检测（SQLite 存储）、参数扰动重试机制、任务状态调度与状态同步。这是整个流程的最后一环，确保生成视频不重复且任务状态正确同步到服务端。

端到端路径：视频生成完成 → 计算 pHash → 与历史视频汉明距离对比 → 判定是否重复 → 若重复则触发重试（扰动参数重新剪辑）→ 若通过则保存视频 → 更新任务状态 → 同步服务端 → 清理临时文件。

## 验收标准

### 重复检测
- [ ] 使用 pHash（基于 DCT 的 64 位哈希）计算视频指纹
- [ ] 与用户所有历史视频哈希记录对比（SQLite 数据库 `hashes/video_hashes.db`）
- [ ] 汉明距离计算，默认阈值 12（≤阈值判定为重复，>阈值标记为通过）
- [ ] 支持根据剪辑模式设置不同阈值
- [ ] 支持缩小检测范围至当前素材或当前任务级别（可配置降级）
- [ ] 哈希计算失败时任务标记为 `failed`
- [ ] 历史记录文件损坏时自动重新创建 SQLite 数据库

### 历史记录管理
- [ ] 支持保留期限配置（默认 30 天）或数量上限（默认 1000 条）
- [ ] 每天定时清理过期记录
- [ ] 记录数达到上限时触发清理

### 重试机制
- [ ] 检测到重复内容时自动触发重试（默认最多 3 次）
- [ ] 参数扰动策略：切换滤镜类别、时长 ±10% 调整、排除已使用背景音乐、调整字体/颜色/位置至差异较大组合
- [ ] 重试耗尽后标记任务为 `failed`，通知服务端

### 任务调度与状态同步
- [ ] 任务状态机：pending → processing → retrying/completed/failed
- [ ] 任务优先级：默认按创建时间排序，支持服务端指定优先级
- [ ] 全局超时 5 分钟（视频剪辑 2 分钟、文案生成 30 秒、重复检测 30 秒），超时标记失败
- [ ] 关键状态变更实时同步：pending → processing → completed/failed 时调用 `PUT /api/tasks/{id}/status`
- [ ] 中间过程状态仅本地记录
- [ ] 同一素材的多个任务默认顺序执行
- [ ] 日志记录任务开始/结束、状态变更、异常触发、重试行为

### 异步检测
- [ ] 视频生成完成后异步触发重复检测，不阻塞主流程
- [ ] 检测完成通过回调通知任务管理模块
- [ ] 用户面板任务列表的重复检测列实时更新（之前显示"-"，检测完成后更新为"通过"或数值）

### 临时文件清理
- [ ] 每个任务完成后立即清理该任务的临时文件
- [ ] 系统启动时清理 `temp/` 目录下超过 24 小时的残留文件

| `/api/tasks/{id}/status` | PUT | 更新任务状态 |
