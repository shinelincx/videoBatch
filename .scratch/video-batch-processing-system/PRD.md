# 视频智能剪辑客户端 PRD

**状态**: `ready-for-agent`

***

## 问题陈述

抖音创作者面临平台防重审查严格、原创性不足导致作品流量受限的问题。现有视频生成流程缺乏系统化的素材管理和重复检测机制，导致：

- 视频生成依赖人工配置，效率低下
- 素材管理混乱，难以追溯和复用
- 生成的视频缺乏原创性保障，容易被平台判定为重复内容
- 没有自动校验和重试机制，需要人工审核

## 解决方案

构建一个视频智能剪辑客户端，核心能力包括：

1. **用户认证**：支持账号密码登录、Token认证，根据用户凭证获取配置和任务
2. **配置同步**：配置参数由服务端管理，客户端通过接口读取并本地缓存
3. **素材管理**：素材由服务端预先生成并存储在本地，每个待剪辑任务以ID标识
4. **多模式剪辑**：支持图生视频、原视频参考等多种剪辑模式
5. **智能去重**：自动进行本地重复性校验，不合格作品自动重新生成
6. **任务监控**：提供可视化的任务管理和状态监控界面
7. **桌面端**：提供图形化用户界面（GUI），支持可视化登录、素材根目录配置及任务列表管理

## 用户故事

1. 作为内容创作者，我希望通过账号密码登录系统，以便获取我的专属配置和任务
2. 作为内容创作者，我希望客户端能自动从服务端获取配置参数，以便快速应用最新的剪辑配置
3. 作为内容创作者，我希望系统根据服务端下发的素材路径自动识别待剪辑素材，以减少手动操作
4. 作为内容创作者，我希望系统支持图生视频模式，以便将图片素材转换为视频作品
5. 作为内容创作者，我希望系统支持原视频参考模式，以便基于已有视频生成新视频
6. 作为内容创作者，我希望每个剪辑任务都有唯一ID标识，以便追踪任务进度和结果
7. 作为内容创作者，我希望系统自动检测生成视频的重复内容，以避免被平台判定为重复
8. 作为内容创作者，我希望当视频检测为重复时自动重新生成，以减少人工干预
9. 作为内容创作者，我希望查看实时的任务状态和剪辑结果，以便及时了解进度
10. 作为内容创作者，我希望通过桌面图形界面启动程序并输入账号密码登录，以便无需命令行操作即可使用系统
11. 作为内容创作者，我希望在用户面板中配置素材根目录路径，以便系统能正确找到我的本地素材
12. 作为内容创作者，我希望在用户面板中查看任务列表（含任务ID、素材ID、配置ID、任务状态），以便清晰了解每个任务的当前情况

## 架构决策参考（ADR）

| ADR编号    | 决策内容   | 说明                                                       |
| -------- | ------ | -------------------------------------------------------- |
| ADR-0001 | 技术栈选择  | 采用 Python + FFmpeg 作为核心技术栈                               |
| ADR-0002 | 重复检测算法 | 使用感知哈希（Perceptual Hashing）算法，具体采用 pHash（基于 DCT 的 64 位哈希） |

## 实现决策

### 核心模块

**架构关系图**：桌面端（GUI） → 用户认证 → 配置同步 → 任务管理 → 素材管理 → 文案生成 → 视频剪辑 → 重复检测 → 重试机制

1. **用户认证模块**
   - 支持账号密码登录、Token认证等方式
   - 登录成功后获取用户凭证（Access Token + Refresh Token）
   - **Token存储**：使用AES-256加密算法本地加密存储，防止凭证泄露
     - **密钥管理**：首次运行时生成随机加密密钥，存储于本地配置目录
     - **安全边界**：防普通用户窥探，不防御有代码访问权限的专业攻击者
   - **Token过期策略**：Access Token有效期设为24小时，Refresh Token有效期设为7天
   - **Token刷新机制**：
     - Access Token过期前1小时自动静默刷新，无需用户操作
     - Refresh Token过期后提示用户重新登录
     - 刷新失败时自动降级为重新登录，保证用户体验
   - **多端登录支持**：支持同一账号同时登录服务端和客户端
   - **冲突处理策略**：
     - 服务端维护会话列表，支持多设备同时在线
     - 客户端检测到异地登录时，提示用户并提供"强制下线其他设备"选项
     - 服务端支持主动踢除指定设备会话
   - 根据用户凭证从服务端下载配置信息
   - 根据用户凭证从服务端获取待剪辑任务列表
   - **异常处理**：网络超时自动重试、认证失败提示重新登录、Token过期自动刷新
2. **配置同步模块**
   - 通过API接口从服务端获取配置参数（支持多配置ID，任务关联具体配置）
   - **配置获取流程**：先获取任务列表获取关联的 config\_id → 再通过 `GET /api/config?config_id=xxx` 拉取对应配置
   - **版本号机制**：配置包含版本号字段，服务端变更时版本号递增，客户端通过版本号检测更新，避免冲突
   - **本地缓存**：配置仅作只读缓存，支持离线使用
   - **配置变更同步**：客户端连接时自动从服务端同步最新配置，禁止本地修改配置
   - **离线模式限制**：仅能执行不依赖服务端API的操作（如本地视频剪辑），需要服务端的操作（如文案生成、任务状态同步）超时后报错并标记任务失败
   - **网络中断处理**：网络中断期间需要服务端的操作直接标记任务失败；网络恢复后客户端重新拉取任务列表继续执行
   - **配置项结构**：
     - 剪辑模式：图生视频、原视频参考
     - 视频项：抽帧、裁剪、模糊、抖动、水印
     - 原视频参考模式专用：
       - 图片拼接到原视频的位置（`img_video_position`）：`"before"`（视频前）或 `"after"`（视频后）
       - 每张图片展示时长（`image_duration`）：单位秒，所有图片统一使用同一时长值
     - 语音项：声音类型、语速（随机值）、背景音乐、变调（是否开启及声音模式由服务端下发）
     - 文本项：字幕、弹幕
     - 前后贴：前贴视频、后贴视频
     - 重复：循环次数（生成 N 个不同版本的视频并拼接）
   - **异常处理**：配置解析失败回滚到上一版本、网络异常使用缓存配置、离线时标记需联网操作并暂停
3. **任务管理模块**
   - 任务由服务端下发，包含任务ID和关联的素材ID
   - 接收服务端任务列表，建立本地任务队列
   - 任务状态管理：待处理（`pending`）、处理中（`processing`）、已完成（`completed`）、失败（`failed`）、重试中（`retrying`）
   - 状态变更时同步到服务端
     - **实时同步**：关键状态变更（`pending` → `processing` → `completed`/`failed`）实时同步
     - **终态同步**：中间过程状态（如剪辑中的子步骤）仅在本地记录，任务达到终态时统一同步
   - 支持任务优先级调度：默认按任务创建时间排序（先到先得），支持服务端指定优先级覆盖默认排序
   - **异常处理**：任务执行超时标记失败（全局超时 5 分钟：视频剪辑 2 分钟、文案生成 30 秒、重复检测 30 秒）、服务端同步失败记录日志并重试
4. **素材管理模块**
   - 解析服务端配置中的素材路径
   - 扫描本地素材目录，建立素材索引
   - 扫描本地配置目录中的 `metadata.json`，获取背景音乐、前贴视频、后贴视频等可选素材的目录
   - 支持图片素材（JPG、PNG、WebP）和视频素材（MP4）的识别
   - 存储素材元数据（路径、类型、尺寸、创建时间）
   - **异常处理**：素材缺失标记任务失败并通知服务端、格式不支持报错提示
5. **文案生成模块**
   - 当配置参数**启用**营销文案需求时，调用服务端配置的AI模型接口
   - 文案生成是否启用由服务端配置控制，非用户手动开关
   - 支持生成多种类型营销文案：产品介绍、促销活动、情感文案等
   - 调用TTS（文字转语音）接口生成音频文件
   - 支持文案风格配置：幽默、正式、亲切、悬疑等
   - 生成的文案和音频可作为视频元素添加到剪辑中（TTS音频**替换**素材中的原始音频）
   - **异常处理**：AI接口调用失败则任务标记为失败、音频生成失败则任务标记为失败
6. **视频剪辑模块**
   - 集成FFmpeg进行视频编码
   - **输出格式**：
     - 视频编码：H.264（兼容性最优）
     - 分辨率：保持与输入素材一致（图生视频模式使用配置默认分辨率；原视频参考模式拼接图生视频时，图生视频需缩放适配原视频参考的分辨率）
     - 帧率：30fps（或保持原素材帧率）
     - 音频编码：AAC
   - **视频处理能力**（根据配置项执行，严格按以下顺序）：
     1. **基础视频生成**：图生视频模式（将单张或多张图片转换为视频）或原视频参考模式（参考已有视频的结构/风格生成新视频）；在原视频参考模式下，若配置了图片视频拼接，则在此步骤将素材目录中的图片按 `image_duration` 转换为视频片段，再与原视频参考按配置的 `img_video_position` 拼接为一个整体
        - **降级策略**：原视频参考模式下，若素材图片目录为空或不存在，则跳过拼接，直接以原始参考视频进入后续处理
     2. **画面处理**：所有操作均引入随机性以解决防重问题
        - 抽帧处理：在5-20帧范围内随机删除一帧
        - 裁剪处理：在上下左右区域随机裁剪1%-2%画面
        - 模糊处理：随机添加1%-3%模糊效果
        - 抖动处理：添加1%-3%的随机画面抖动效果
        - 亮度设置：随机添加亮度处理效果，随机值通过本地配置文件设置-0.2到0.2
        - 对比度设置：随机添加对比度处理效果，随机值通过本地配置文件设置0.5到1.5
        - 饱和度设置：随机添加饱和度处理效果，随机值通过本地配置文件设置0.5到1.5
        - 色彩平衡设置：随机添加色彩平衡处理效果，红绿蓝随机值通过本地配置文件设置-0.2到0.2
        - 伽马值设置：随机添加伽马值处理效果，随机值通过本地配置文件设置0.5到1.5
        - 复古黑白设置：随机添加复古黑白处理效果，随机值通过本地配置文件设置0.5到1.5
     3. **拼接处理**：从配置目录中随机选择前贴视频、后贴视频进行拼接
     4. **叠加元素**：
        - 水印处理：从目录随机选择自定义水印，设置10%-30%的随机透明度及运动轨迹
        - 字幕：文字样式随机（字体、大小、颜色、位置在配置范围内随机变动）
        - 弹幕效果：使用预设文本，字体、颜色、速度在配置范围内随机，密度由配置参数控制
        - 贴纸：从本地配置目录随机选择贴纸，在视频4个角随机出现1-4个贴纸，设置10%-30%的随机透明度及小范围运动轨迹
     5. **文案与音频生成**（可选，根据配置启用）：
        - 文案生成：调用AI接口生成营销文案
        - TTS音频生成：将文案转换为语音文件，替换素材中的原始音频
     6. **音频处理**：
        - 背景音乐：从配置的音乐列表中随机选取
        - 语速调整：从本地配置文件获取随机值范围，执行时随机选取语速值
        - 变调处理（可选，根据配置启用）：
          - 变调值由本地配置文件定义随机半音数范围（如 -5 \~ +5 半音），执行时随机选取
          - 是否启用由服务端下发配置控制，具体变调值完全由本地随机范围决定
          - 通过FFmpeg rubberband音频滤镜实现变调效果
   - **重复处理**：按配置次数生成 N 个不同版本的视频并拼接（最后执行）
   - **随机性配置管理**：
     - **配置文件**：随机化配置独立存储在客户端本地配置文件中，不属于服务端配置，用于定义各随机项的取值范围
     - **配置选择**：执行时根据服务端配置参数决定启用哪些随机选项，从本地配置文件获取取值范围并生成随机值
     - **日志记录**：每次任务完成后，将生成的随机值同步保存到任务日志中，便于调试和问题复现
     - **质量保障**：随机参数设置以不影响用户观感为前提，限制随机范围在合理区间
     - **防重效果验证**：通过感知哈希（Perceptual Hashing）算法检测视频相似度进行验证
     - **动态调整支持**：支持配置参数的动态调整，无需重启即可应用新的随机策略
   - **异常处理**：FFmpeg执行失败标记任务失败（属于不可恢复异常）、输出路径不存在自动创建
7. **重复检测模块**
   - 使用感知哈希（Perceptual Hashing）算法，具体采用 **pHash**（基于 DCT 的 64 位哈希）检测视频相似度
   - 与**该用户的所有历史视频**对比
   - **可配置降级**：支持缩小检测范围至当前素材或当前任务级别，以平衡性能与检出率
   - **相似度阈值**：可配置，采用汉明距离计算，默认阈值为 12（64 位 pHash 中最多允许 12 位不同，约对应 81% 相似度），支持根据剪辑模式设置不同阈值
   - **异步检测支持**：支持异步检测模式，避免阻塞主流程
     - **触发时机**：每个视频生成完成后立即触发异步检测
     - **结果回调**：检测完成后通过回调机制通知任务管理模块
     - **自动重试**：若检测到重复，任务管理模块自动触发重试流程
   - **历史记录管理**：支持配置保留期限（默认30天）或数量上限（默认1000条），每天自动清理过期记录
   - **存储方案**：支持本地JSON文件和SQLite数据库两种方案（见下文选择）
   - **异常处理**：哈希计算失败标记任务失败、历史记录文件损坏重新创建
8. **重试机制模块**
   - 检测到重复内容时自动重新生成
   - 可配置重试次数（默认3次）
   - **参数扰动策略**：重试时在原有参数基础上做显著偏移，而非完全随机
     - 滤镜：切换到不同类别的滤镜
     - 时长：在安全范围内做更大幅度的调整（±10%）
     - 背景音乐：从列表中排除已使用过的音乐
     - 文字样式：调整字体、颜色、位置至与原方案差异较大的组合
   - **异常处理**：重试耗尽标记任务失败并通知服务端
9. **桌面端模块**
   - 提供图形化用户界面（GUI），降低使用门槛，无需命令行操作
   - **页面流程**：启动 → 登录页 → 用户面板
   - **登录页**：
     - 输入用户名和密码，点击登录按钮调用 `/api/auth/login` 接口
     - 登录成功后自动跳转至用户面板
     - 登录失败时在界面显示错误提示信息
     - 支持记住用户名功能（本地明文存储用户名，不存储密码）
   - **用户面板**：
     - **素材根目录配置**：
       - 提供输入框或目录选择器，允许用户配置本地素材根目录路径
       - 配置保存到本地配置文件，下次启动自动加载
       - 支持修改后实时生效，无需重启
     - **任务列表**：
       - 以表格形式展示从服务端获取的任务列表
       - 列表列包含：任务ID、素材ID、配置ID、任务状态、重复检测
       - **重复检测**：显示最近一次重复检测的汉明距离。若汉明距离 > 相似度阈值则标记为"通过"，否则显示实际数值；未检测时显示"-"
       - **素材查看**：支持点击任务行查看该任务关联的素材（若存在），以独立窗口播放；所有任务状态均可查看
       - **视频查看**：支持点击任务行查看已生成的视频（若存在），以独立窗口播放；仅在任务为 `completed` 或 `failed` 终态时可用
       - 支持按状态筛选（全部 / 待处理 / 处理中 / 重试中 / 已完成 / 失败）
       - 支持手动刷新任务列表
       - 任务状态变更时自动更新列表显示
   - **架构设计**：
     - 桌面端作为前端展示层，通过调用后端模块（认证、配置同步、任务管理等）的 API 完成业务逻辑
     - 桌面端不包含业务逻辑，仅负责用户交互和数据展示
     - 后端核心模块与桌面端解耦，可独立运行（命令行模式）或被 GUI 调用
   - **异常处理**：GUI 线程异常不阻塞后端任务处理、界面卡死时支持强制刷新

### 数据模型（服务端视角）

> 以下数据模型统一采用服务端视角建模。客户端缓存不纳入数据模型，其结构由本地实现决定。

| 模型           | 字段                                                                                 | 说明     |
| ------------ | ---------------------------------------------------------------------------------- | ------ |
| **User**     | id, username, refresh\_token, refresh\_token\_expires\_at, created\_at             | 用户实体   |
| **Config**   | id, user\_id, version, parameters, last\_sync\_time                                | 配置实体 |

> `mode` 字段使用字符串枚举：`image-to-video`（图生视频）、`reference-video`（原视频参考）

### 临时文件清理策略

- **任务完成清理**：每个任务完成后立即清理该任务产生的临时文件
- **残留清理**：系统启动时自动清理 `temp/` 目录下超过 24 小时的残留文件

### 核心业务流程

```
启动桌面端 → 登录页（输入用户名密码）→ 认证成功/获取Token → 用户面板 → 配置素材根目录 →
获取配置 → 获取待剪辑任务 → 解析配置 → 加载素材 → 生成文案（可选）→
    ├─ 文案成功 → 视频剪辑 → 重复检测 →
    │   ├─ 通过 → 保存视频 → 更新状态 → 同步服务端
    │   └─ 重复 → 重试机制 → 重新剪辑
    │       ├─ 通过 → 保存视频 → 更新状态 → 同步服务端
    │       └─ 重试耗尽 → 任务标记失败 → 通知服务端 → 结束
    └─ 文案失败 → 任务标记失败 → 通知服务端 → 结束
```

### 异常处理流程

**异常分类**：

1. **可重试异常**：网络超时、临时服务不可用（自动重试，最多3次）
2. **不可恢复异常**：配置错误、素材格式不支持、素材缺失（直接标记任务失败）
3. **业务策略异常**：文案生成失败、AI接口调用失败（根据业务规则决定处理方式，如标记失败或跳过）

```
异常触发 → 记录日志 → 判断异常类型 → 
    ├─ 可重试异常 → 自动重试（最多3次） → 
    │   ├─ 成功 → 继续流程
    │   └─ 失败 → 标记任务失败 → 通知服务端
    ├─ 不可恢复异常 → 标记任务失败 → 通知服务端 → 用户提示
    └─ 业务策略异常 → 按业务规则处理 → 
        ├─ 标记失败 → 通知服务端
        └─ 跳过环节 → 记录日志 → 继续流程
```

## 测试决策

### 模块测试

- **用户认证测试**：验证账号密码登录、Token认证、会话保持的正确性，覆盖网络超时、认证失败、Token过期场景
- **配置同步测试**：验证从服务端获取配置、本地缓存和同步更新的正确性，覆盖配置解析失败、网络异常场景
- **任务管理测试**：验证任务接收、队列管理和状态同步的正确性，覆盖任务超时、同步失败场景
- **素材识别测试**：验证根据配置路径正确识别图片和视频素材，覆盖素材缺失、格式不支持场景
- **文案生成测试**：验证AI文案生成和TTS音频生成的正确性，覆盖接口调用失败场景
- **视频剪辑测试**：验证图生视频、原视频参考模式及各项视频处理功能，覆盖FFmpeg执行失败场景
- **重复检测测试**：验证相似度检测算法的准确性，覆盖哈希计算失败、历史记录损坏场景
- **重试机制测试**：验证重复视频自动重新生成的机制，覆盖重试耗尽场景
- **桌面端测试**：验证登录页输入校验、登录成功/失败跳转逻辑的正确性；验证用户面板素材根目录配置的保存与加载；验证任务列表数据展示、状态筛选和自动刷新的正确性

### 集成测试

- **端到端流程测试**：完整流程从登录→获取配置→获取任务→生成文案→视频剪辑→重复检测→输出，验证各模块协同工作
- **并发任务测试**：多个任务并行处理时的资源竞争、状态同步和素材访问冲突
- **长时间运行测试**：连续处理大量任务时的内存泄漏、资源释放和数据库性能

## 非功能需求

- **性能**：单任务视频生成时间 < 30秒
  - **测试条件**：输入素材为 1080p、时长不超过 60 秒的视频
  - **计算范围**：仅包含纯剪辑处理时间（从基础视频生成到重复检测完成），不含文案生成和网络同步
- **可靠性**：重复检测准确率
  - **召回率** > 95%（真正重复的视频 95% 能被检测出来）
  - **精确率** > 80%（避免误杀率过高导致大量重试）
- **扩展性**：支持并行处理多个视频任务
  - **系统层面**：架构支持并行处理不同素材的任务
  - **素材层面**：同一素材关联的多个任务默认顺序执行，以避免资源竞争
  - **可配置**：支持通过配置将同素材任务改为并行执行
- **可用性**：提供清晰的错误提示和日志记录
  - **日志级别**：INFO（关键流程节点）和 ERROR（异常）
  - **日志格式**：`[时间戳] [任务ID] [模块] [级别] 消息`
  - **关键节点**：任务开始/结束、状态变更、异常触发、重试行为必须记录
- **离线支持**：配置缓存后支持离线剪辑
- **桌面端可用性**：
  - 界面响应时间 < 500ms（登录、任务列表加载等用户操作）
  - 支持 Windows 10/11 操作系统
  - 界面布局清晰，登录页和用户面板功能分区明确
  - 错误提示以对话框或内联提示形式展示，信息清晰可读

## 范围之外

- 不包含抖音平台直接发布功能
- 不包含用户交互式视频编辑功能（如手动裁剪、特效编辑、时间轴调整）
- 不包含云端存储集成（仅本地存储）
- 不包含桌面端的 Web 浏览器版本（仅提供原生桌面客户端）

## 存储方案选择

### 哈希记录存储方案对比

| 方案            | 优点               | 缺点                  | 适用场景                   |
| ------------- | ---------------- | ------------------- | ---------------------- |
| **JSON文件**    | 简单直观、无需额外依赖、易于调试 | 读写效率低、不支持索引、并发访问不安全 | 小规模部署（<1000条记录）、开发调试阶段 |
| **SQLite数据库** | 查询效率高、支持索引、事务安全  | 需要学习SQL语法、文件相对复杂    | 中大规模部署（>1000条记录）、生产环境  |

### 推荐方案

**建议默认使用 SQLite 数据库方案**，原因如下：

1. **性能优势**：支持索引查询，大数据量下查询速度远快于JSON文件
2. **数据安全**：支持事务，避免并发写入冲突
3. **扩展性好**：便于后续扩展复杂查询需求

### 清理策略

- **定时清理**：每天定时运行清理任务，删除过期记录
- **触发清理**：当记录数达到上限时触发清理

## 其他说明

系统采用模块化设计，各模块之间通过接口解耦，便于后续扩展和维护。重复检测算法可根据实际需求替换为更先进的方案。建议使用Python作为主要开发语言，便于快速集成FFmpeg和图像处理库。
