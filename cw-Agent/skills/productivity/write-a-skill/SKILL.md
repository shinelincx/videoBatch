# 编写 Skill

## 流程（Process）

1. **收集需求** - 向用户了解：
   - 该 skill 负责什么任务/领域？
   - 需要处理哪些具体用例？
   - 需要可执行脚本还是仅指令说明？
   - 有需要包含的参考资料吗？

2. **起草 skill** - 创建：
   - SKILL.md，包含简洁的说明
   - 如果内容超过 500 行，提供额外的参考文件
   - 如果需要确定性操作，提供工具脚本

3. **与用户评审** - 展示草稿并询问：
   - 是否覆盖了你的用例？
   - 有没有遗漏或不清晰的地方？
   - 某些部分是否需要更详细或更简略？

## Skill 结构（Skill Structure）

```
skill-name/
├── SKILL.md           # 主说明文件（必需）
├── REFERENCE.md       # 详细文档（按需）
├── EXAMPLES.md        # 使用示例（按需）
└── scripts/           # 工具脚本（按需）
    └── helper.js
```

## SKILL.md 模板（Template）

```md
---
name: skill-name
description: 简要描述功能。当 [具体触发条件] 时使用。
---

# Skill 名称

## 快速开始（Quick start）

[最小可用示例]

## 工作流（Workflows）

[分步流程，复杂任务附带检查清单]

## 高级功能（Advanced features）

[链接到独立文件：参见 [REFERENCE.md](REFERENCE.md)]
```

## 描述要求（Description Requirements）

描述是 **agent 决定是否加载 skill 时唯一看到的内容**。它会与其他所有已安装的 skill 一起出现在系统提示中。agent 会阅读这些描述，并根据用户请求选择相关的 skill。

**目标**：让 agent 只需了解：

1. 这个 skill 提供什么能力
2. 何时/为何触发它（具体关键词、上下文、文件类型）

**格式**：

- 最多 1024 字符
- 使用第三人称书写
- 第一句：它能做什么
- 第二句："当 [具体触发条件] 时使用"

**好的示例**：

```
从 PDF 文件中提取文本和表格、填写表单、合并文档。当处理 PDF 文件或用户提及 PDF、表单或文档提取时使用。
```

**差的示例**：

```
帮助处理文档。
```

差的示例让 agent 无法将此 skill 与其他文档类 skill 区分开来。

## 何时添加脚本（When to Add Scripts）

满足以下条件时添加工具脚本：

- 操作是确定性的（验证、格式化）
- 同一代码会被反复生成
- 需要明确的错误处理

脚本比生成的代码更节省 token 且更可靠。

## 何时拆分文件（When to Split Files）

满足以下条件时拆分为独立文件：

- SKILL.md 超过 100 行
- 内容涉及不同领域（如财务 vs 销售模式）
- 高级功能很少用到

## 评审清单（Review Checklist）

起草完成后，确认以下各项：

- [ ] 描述中包含触发条件（"当...时使用"）
- [ ] SKILL.md 不超过 100 行
- [ ] 不含时效性信息
- [ ] 术语保持一致
- [ ] 包含具体示例
- [ ] 保持一层引用深度
