# Triage（分诊）

将项目 Issue 追踪器上的 Issue 通过小型分诊角色状态机进行流转。

分诊期间在 Issue 追踪器上发布的每条评论或 Issue **必须**以以下免责声明开头：

```
> *此内容由 AI 在分诊过程中生成。*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何编写持久的 agent 简报
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 知识库如何工作

## 角色

两种**类别**角色：

- `bug`——某些东西坏了
- `enhancement`——新功能或改进

五种**状态**角色：

- `needs-triage`——维护者需要评估
- `needs-info`——等待报告者提供更多信息
- `ready-for-agent`——规格完整，可供离线 agent 处理
- `ready-for-human`——需要人类实现
- `wontfix`——不会被处理

每个经过分诊的 Issue 应恰好携带一个类别角色和一个状态角色。如果状态角色冲突，标记并询问维护者，然后再做任何事情。

这些是标准角色名称——Issue 追踪器中实际使用的标签字符串可能不同。映射应该已提供给你——如果没有，运行 `/setup-matt-pocock-skills`。

状态转换：未标记的 Issue 通常先转到 `needs-triage`；从那里可以移动到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。一旦报告者回复，`needs-info` 返回 `needs-triage`。维护者可以随时覆盖——标记看起来不寻常的转换，在继续之前询问。

## 调用方式

维护者调用 `/triage` 并用自然语言描述他们想要的操作。解释请求并执行。例如：

- "给我看任何需要我关注的东西"
- "看看 #42"
- "把 #42 移到 ready-for-agent"
- "哪些准备好让 agent 接手了？"

## 展示需要关注的内容

查询 Issue 追踪器并呈现三个桶，从最旧的开始：

1. **未标记**——从未分诊过。
2. **`needs-triage`**——评估进行中。
3. **`needs-info` 且报告者在上次分诊说明后有活动**——需要重新评估。

显示每个 Issue 的数量和一行摘要。让维护者选择。

## 分诊特定 Issue

1. **收集上下文。** 读取完整 Issue（正文、评论、标签、报告者、日期）。解析之前的分诊说明，这样你不会重复询问已解决的问题。使用项目的领域词汇表探索代码库，遵守涉及区域的 ADR。读取 `.out-of-scope/*.md` 并呈现任何与当前 Issue 相似的先前拒绝。

2. **推荐。** 告诉维护者你的类别和状态推荐及理由，加上与 Issue 相关的代码库摘要。等待指示。

3. **复现（仅 Bug）。** 在任何追问之前，尝试复现：读取报告者的步骤、追踪相关代码、运行测试或命令。报告发生了什么——成功复现及代码路径、复现失败、或细节不足（强烈的 `needs-info` 信号）。确认的复现能产生更强大的 agent 简报。

4. **追问（如需要）。** 如果 Issue 需要补充，运行 `/grill-with-docs` 会话。

5. **应用结果：**
   - `ready-for-agent`——发布 agent 简报评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human`——与 agent 简报结构相同，但说明为什么不能委托（判断决策、外部访问、设计决策、手动测试）。
   - `needs-info`——发布分诊说明（模板见下方）。
   - `wontfix`（Bug）——礼貌解释，然后关闭。
   - `wontfix`（功能增强）——写入 `.out-of-scope/`，从评论中链接到它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage`——应用角色。如果有部分进展，可选添加评论。

## 快速状态覆盖

如果维护者说"把 #42 移到 ready-for-agent"，信任他们并直接应用角色。确认你要做什么（角色变更、评论、关闭），然后执行。跳过追问。如果在没有追问会话的情况下移到 `ready-for-agent`，询问他们是否想编写 agent 简报。

## Needs-info 模板

```markdown
## 分诊说明

**目前为止已确认的内容：**

- 要点 1
- 要点 2

**我们还需要你提供的信息（@reporter）：**

- 问题 1
- 问题 2
```

将追问期间解决的所有内容捕获到"目前为止已确认"下，这样工作不会丢失。问题必须具体且可操作，而不是"请提供更多信息"。

## 恢复之前的会话

如果 Issue 上存在先前的分诊说明，读取它们，检查报告者是否回答了任何未解决的问题，在继续之前呈现更新后的情况。不要重复询问已解决的问题。
