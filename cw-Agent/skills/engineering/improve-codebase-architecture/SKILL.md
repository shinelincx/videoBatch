# Improve Codebase Architecture

发现架构摩擦并提出**深化机会**——将浅层模块转化为深层模块的重构。目标是可测试性和 AI 可导航性。

## 术语表

在每条建议中精确使用以下术语。使用一致的语言是核心——不要漂移到"组件"、"服务"、"API"或"边界"。完整定义见 [LANGUAGE.md](LANGUAGE.md)。

- **Module（模块）**——任何具有接口和实现的东西（函数、类、包、切片）。
- **Interface（接口）**——调用者使用模块所需知道的一切：类型、不变量、错误模式、顺序、配置。不只是类型签名。
- **Implementation（实现）**——内部的代码。
- **Depth（深度）**——接口处的杠杆率：小接口背后隐藏大量行为。**深层（Deep）**= 高杠杆率。**浅层（Shallow）**= 接口复杂度几乎等于实现复杂度。
- **Seam（接缝）**——接口所在之处；行为可以在不就地修改的情况下被改变的地方。（用这个词，不要用"边界"。）
- **Adapter（适配器）**——在接缝处满足接口的具体事物。
- **Leverage（杠杆率）**——调用者从深度中获得的东西。
- **Locality（局部性）**——维护者从深度中获得的东西：变更、Bug、知识集中在一个地方。

关键原则（完整列表见 [LANGUAGE.md](LANGUAGE.md)）：

- **删除测试**：想象删除这个模块。如果复杂度消失了，它只是一个透传层。如果复杂度在 N 个调用者中重新出现，它就在发挥作用。
- **接口即测试面。**
- **一个适配器 = 假设的接缝。两个适配器 = 真实的接缝。**

此 skill 受项目的领域模型**指导**。领域语言为好的接缝命名；ADR 记录 skill 不应重新争论的决策。

## 流程

### 1. 探索

首先阅读项目的领域词汇表和你涉及区域的 ADR。

然后使用 Agent 工具配合 `subagent_type=Explore` 遍历代码库。不要遵循僵化的启发式规则——有机地探索，注意你在哪里感受到摩擦：

- 理解一个概念需要在许多小模块之间跳转的地方在哪里？
- 模块**浅层**的地方在哪里——接口复杂度几乎等于实现复杂度？
- 纯函数仅仅为了可测试性被提取出来，但真正的 Bug 隐藏在它们被调用的方式中（缺少**局部性**）的地方在哪里？
- 紧耦合模块在接缝处泄漏的地方在哪里？
- 代码库的哪些部分未测试，或通过当前接口难以测试？

对任何你怀疑是浅层的东西应用**删除测试**：删除它会让复杂度集中吗，还是只是转移了？"是的，集中了"就是你想要的信号。

### 2. 呈现候选方案

以编号列表形式呈现深化机会。对于每个候选方案：

- **文件**——涉及哪些文件/模块
- **问题**——当前架构为什么造成摩擦
- **解决方案**——用自然语言描述会改变什么
- **收益**——从局部性和杠杆率角度解释，以及测试会如何改进

**领域相关词汇使用 CONTEXT.md 中的术语，架构相关词汇使用 [LANGUAGE.md](LANGUAGE.md) 中的术语。** 如果 `CONTEXT.md` 定义了"Order"，就谈"Order 接入模块"——而不是"FooBarHandler"，也不是"Order 服务"。

**与 ADR 冲突**：如果候选方案与现有 ADR 矛盾，仅在摩擦足够严重值得重新审视 ADR 时才提出。明确标注（例如 _"与 ADR-0007 矛盾——但值得重新打开，因为…"_）。不要列出 ADR 禁止的每个理论上的重构。

暂时不要提出接口设计。先问用户："你想探索哪个方案？"

### 3. 追问循环

用户选择候选方案后，进入深度追问对话。和他们一起遍历设计树——约束条件、依赖关系、深化模块的形态、接缝背后是什么、哪些测试保留下来。

决策确定时会产生副作用：

- **以 `CONTEXT.md` 中不存在的概念命名深化模块？** 将术语添加到 `CONTEXT.md`——与 `/grill-with-docs` 相同的规范（见 [CONTEXT-FORMAT.md](../grill-with-docs/CONTEXT-FORMAT.md)）。如果文件不存在则延迟创建。
- **在对话中打磨了模糊术语？** 立刻更新 `CONTEXT.md`。
- **用户以具有充分理由的理由拒绝候选方案？** 提议创建 ADR，措辞为：_"要我把它记录为 ADR 吗？这样未来的架构审查就不会再提出它了。"_ 仅在理由确实需要被未来的探索者知晓以避免重复建议时才提议——跳过临时性理由（"现在不值得"）和不言自明的理由。见 [ADR-FORMAT.md](../grill-with-docs/ADR-FORMAT.md)。
- **想探索深化模块的替代接口？** 见 [INTERFACE-DESIGN.md](INTERFACE-DESIGN.md)。
