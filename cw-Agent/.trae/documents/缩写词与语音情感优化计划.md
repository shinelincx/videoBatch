# 外语文案缩写词解读 + 语音情感优化计划

## 问题分析

### 问题 1：缩写词没有准确解读
当前 LLM 生成外语文案时，会直接使用缩写词（如 `ROI`、`KOL`、`UGC`、`CTA` 等），而 TTS 引擎（edge-tts）会把缩写词逐个字母读出（如 "R-O-I" 而非 "return on investment"），导致语音听感差。

**根因**：整个链路缺少缩写词展开处理：
- LLM Prompt 没有要求避免缩写词
- TTS 调用前没有对文案做缩写词展开
- 代码库中没有缩写词字典

### 问题 2：语音语调单一，没有感情
当前所有语言的 TTS 都使用固定语速 + 固定音色，没有任何 SSML 韵律控制，整段文案从头到尾一个调，缺少：
- 开头钩子句的紧张/惊讶感
- 正文描述的平稳叙述感
- 结尾 CTA 的催促/紧迫感

**根因**：`text_to_speech()` 仅做了文本清洗就直传 edge_tts，没有利用 SSML `<prosody>` 标签控制语速和音调变化。

### 模块二：语音情感化 (`app/emotion.py`)

#### 2.1 文案分段策略
根据 Skill 的执行步骤，将文案按语义分段：

| 段落类型 | 情感基调 | 语速变化 | 音调变化 | 停顿 |
|---------|---------|---------|---------|------|
| 开头 Hook | 紧张/惊讶/好奇 | `rate="+10%"` | `pitch="+8%"` | 后加 0.3s 停顿 |
| 痛点/问题 | 共鸣/理解 | `rate="-5%"` | `pitch="-3%"` | 后加 0.2s 停顿 |
| 产品展示/正文 | 平稳/可信 | `rate="0%"` | `pitch="0%"` | 句子间正常 |
| 促单 CTA | 紧迫/激励 | `rate="+8%"` | `pitch="+5%"` | 前加 0.3s 停顿 |

#### 2.2 基于标点的自动分段
如果不能精确识别段落边界，使用基于标点和句子类型的启发式规则：
- **疑问句**（以 `？/?` 结尾）→ 升高语调和语速
- **感叹句**（以 `！/!` 结尾）→ 升高音调
- **首句** → Hook 情感
- **末句** → CTA 情感
- **中间部分** → 平稳叙述

#### 2.3 SSML 包装
将分词后的文案包装为 edge_tts 兼容的 SSML 格式：

```xml
<speak version="1.0" xmlns="http://www.w3.org/2001/10/synthesis" xml:lang="en-US">
  <prosody rate="+10%" pitch="+8%">I can't believe this actually works!</prosody>
  <break time="300ms"/>
  <prosody rate="0%" pitch="0%">This serum literally transformed my skin in just 7 days...</prosody>
  <break time="300ms"/>
  <prosody rate="+8%" pitch="+5%">Grab yours now before it sells out!</prosody>
</speak>
```

#### 2.4 多语种适配
不同语种的语速和音调基线不同，需要按语种差异化调整：
- 英语：基线语速 3，情感变化幅度 ±10%
- 日语：基线语速 5，情感变化幅度 ±8%
- 韩语：基线语速 4，情感变化幅度 ±10%
- 其他语种类似

## 风险与注意事项

1. **SSML 兼容性**：edge_tts 对 SSML 标签的支持有限，需要在实际测试中验证 `<prosody>` 和 `<break>` 标签是否生效。若不支持完整 SSML，可降级为拆分文本、多次调用 TTS 后拼接音频的方案。

2. **缩写词误替换**：需要仔细处理边界，避免将普通全大写单词（如品牌名 "MAC"、技术术语 "API"）误替换。

3. **字幕同步**：SSML 标签会影响 TTS 的 word_boundaries 偏移量计算。需要在 `generate_srt()` 中处理 SSML 标签的去除。

4. **向后兼容**：新增情感开关 `EMOTION_ENABLED`（默认启用），允许用户关闭该功能。
