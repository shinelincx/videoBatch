# grilling 期间的问题数量上限

`/grill-me` skill（以及其他 skill 中的 grilling 环节）不会强制限制最大问题数量。添加可配置上限或硬性上限的请求不在范围内。

## 为什么不在此范围内

Grilling 的设计就是开放式的。目的是持续深入挖掘，直到决策树的每个分支都被解决——有些计划需要三个问题，有些则需要五十个。固定的上限要么会在困难问题上切断有用的探索，要么在简单问题上显得随意。

如果某个环节感觉太长，现有的退出机制已经足够：

- 用户可以随时停止环节并接受计划的当前状态。
- 用户可以告诉模型进行总结并继续前进——自然语言引导才是预期的控制方式，而不是数字限制。

添加硬性上限还会混淆两种不同的失败模式：模型因为计划确实不够明确而提出过多问题（正常工作）vs 模型提出冗余或低价值的问题（prompt 质量问题，而非数量问题）。后者的修复应该放在 skill prompt 中，而不是计数器里。
